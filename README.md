# Iris

**A second pair of eyes on every page.** Iris is a voice copilot in your browser. It reads the page with you and gives you a heads-up before you fill a form, agree to terms, pay, or trust a site. Ask it anything out loud; it answers from the page, points at the exact clause, and speaks up by itself when something will cost you.

It never clicks, types or submits anything, and no form field value ever leaves the page.

Built for the AssemblyAI Voice Agent Hackathon.

## What it does

- **Before you pay:** works out the true cost of an offer ("1.5% a month flat" is about 36.5% a year) and flags pre-ticked add-ons and hidden fees at checkout, with a soft chime before it speaks up.
- **Before you agree:** answers questions about long terms and privacy policies, highlights the clause it quotes, and explains anything you hover over.
- **Before you fill:** walks you through a form part by part and explains any field you point at.
- **Before you trust:** checks a site's domain age, look-alike names and public scam reports, and looks things up on the web.
- **Across pages:** remembers what you saw on earlier pages in the same tab ("the fee on the last page was ₹1,416").

## How it's built

| Part | Folder | Stack |
|---|---|---|
| Chrome extension (side panel) and an embeddable widget | `extension/` | TypeScript, Preact, WXT (Manifest V3) |
| Backend: voice tokens, the agent's tools, spend caps | `backend/` | Python 3.13, FastAPI |
| Demo site: a landing page and QuickCred, a fictional lender with the tricks real sites use, with Iris built in as a widget | `demo-site/` | Astro (static) |

- **Voice:** [AssemblyAI's Voice Agent API](https://www.assemblyai.com/docs) handles listening, turn-taking, interruptions and Iris's voice. The browser talks to it directly with a short-lived token from the backend, and the agent calls Iris's tools as client-side tools.
- **Reading and reasoning:** Claude, through AssemblyAI's LLM Gateway, for long terms, page questions and scans.
- **The web:** [Tavily](https://tavily.com) for search, and RDAP for domain ages.
- **Figures come from code:** costs, rates, dates and domain ages are calculated, never generated by the model, and every quote is checked against the page text.

## Run it locally

Needs Node 24 with pnpm (through Corepack), [uv](https://docs.astral.sh/uv/), and Chrome.

```sh
corepack enable pnpm
pnpm install
cd backend && uv sync && cp .env.example .env && cd ..
```

### Try it without any API keys

Fake mode swaps every paid service for a deterministic fake, and mock voice replaces the microphone with a text box. The answers are placeholders, but the whole interface works.

```sh
# Terminal 1: the backend in fake mode
cd backend
IRIS_FAKE_UPSTREAMS=1 DATA_DIR=.data uv run uvicorn app.main:app --port 8000 --no-access-log

# Terminal 2: the demo site, with Iris built in
pnpm --filter demo-site dev
```

Open http://localhost:4321/demo/?iris_mock_voice=1 and open Iris from the button at the bottom of the page. To try the extension the same way, build it with mock voice and load it (below):

```sh
IRIS_API_BASE=http://localhost:8000/api IRIS_MOCK_VOICE=true pnpm --filter extension build
```

### With real voice and answers

Put your `ASSEMBLYAI_API_KEY` and `TAVILY_API_KEY` in `backend/.env`, then:

```sh
cd backend && DATA_DIR=.data uv run uvicorn app.main:app --port 8000 --no-access-log
IRIS_API_BASE=http://localhost:8000/api pnpm --filter extension build
```

The demo pages' widget uses real voice too (drop `?iris_mock_voice=1`). The backend refuses paid calls beyond the daily and total caps in `.env` (`BUDGET_DAILY_USD`, `BUDGET_TOTAL_USD`).

### Load the extension

1. Open `chrome://extensions` and turn on **Developer mode**.
2. Click **Load unpacked** and choose `extension/.output/chrome-mv3`.
3. Open any page (the demo site's `/demo/` pages are a good start), click the Iris icon, and start talking. **Alt+Shift+I** opens Iris and starts or ends a session.

## Tests

Every suite runs in fake mode with mock voice: no keys, no paid calls.

| Part | Command |
|---|---|
| Backend | `cd backend && uv run pytest`, plus `uv run ruff check` and `uv run mypy --strict app` |
| Extension | `pnpm --filter extension test` (unit) and `pnpm --filter extension e2e` (browser) |
| Demo site | `pnpm --filter demo-site test` |

The browser tests need Chromium once: `pnpm --filter extension exec playwright install chromium`.

## Deploy

The backend runs as one always-on container, because it keeps page snapshots in memory and its spend ledger in SQLite. The demo site is static.

### Backend on Railway

1. New project → **Deploy from GitHub repo** → this repo.
2. In the service's **Settings**: set **Root Directory** to `backend` and **Config file path** to `/backend/railway.json`. It builds with `backend/Dockerfile`.
3. Add a **Volume** mounted at `/data` (the spend ledger lives there).
4. Add the variables from `backend/.env.example`, with at least:
   - `IRIS_ENV=prod`
   - `ASSEMBLYAI_API_KEY` and `TAVILY_API_KEY`
   - `IRIS_PUBLIC_URL=https://<your-backend-domain>`
   - `ALLOWED_ORIGINS=chrome-extension://kjcchlmlkmljbpaobhidapkobbbdfmap,https://<your-site-domain>`: the extension, and the demo pages' widget, which calls the backend from your site's domain
   - `RAILWAY_RUN_UID=0` (the image runs as a non-root user, and this lets it write to the volume)
5. **Networking** → **Generate Domain**, with port `8000`. Check `https://<your-backend-domain>/api/health`.

### Demo site on Vercel

1. **Add New Project** → import this repo, leaving **Root Directory** as the repo root. `vercel.json` sets the install and build commands and the output folder.
2. Add the environment variables:
   - `IRIS_API_BASE=https://<your-backend-domain>/api`: the demo pages' widget calls it, and the extension download on the landing page is built against it
   - `IRIS_PUBLIC_URL=https://<your-site-domain>`
   - `ENABLE_EXPERIMENTAL_COREPACK=1`, so the build uses the pnpm version in `package.json`
   - Optional: `IRIS_GITHUB_URL` and `IRIS_VIDEO_URL` for the landing page's links, and `IRIS_DEMO_WIDGET=false` to leave the widget off the demo pages
3. Deploy. Visitors can talk to Iris on `/demo/` straight away, and the landing page offers the extension zip at `/downloads/iris-extension.zip`.

The extension's ID is fixed by the public key in `extension/wxt.config.ts`, so `ALLOWED_ORIGINS` stays the same for every build.

## Privacy, enforced in code

- Snapshots say whether a field is filled, never what's in it. The backend rejects any `value` key at any depth.
- Page content is held in memory for 30 minutes after last use, and is never logged or stored.
- Logs carry allow-listed fields only: no page text, questions, answers or URLs.
- With the side panel closed, nothing is sent anywhere.
